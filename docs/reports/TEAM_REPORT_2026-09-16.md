## 1. 結論（先に要点）

- **現時点のベストは Public LB 0.87505（提出 M）**。前回ベストの L（0.86893）から **+0.0061**。
  - データが作り直された 9/11 以降の提出に限ると、9/15 時点で3位（1位 0.92406、2位 0.92226）。
- **M は L の Task 2 に「時空間 CNN」を足して、LightGBM と混ぜたもの。** Task 1・3・4 は L と同じ。

  | タスク | 手法 |
  |---|---|
  | Task 1 | CNN 3モデルの平均＋月ごとの補正＋採点月でのテスト時学習（L と同じ） |
  | Task 2 onset | **0.7 × LightGBM ＋ 0.3 × CNN（3本の平均）**、IoU 期待値最大化で判定 |
  | Task 2 ongoing | **0.5 × LightGBM ＋ 0.5 × CNN（3本の平均）**、確率0.60以上を渋滞 |
  | Task 3 | Task 1 の予測がそのまま使われる |
  | Task 4 | 各月の公開リンク交通量で非負最小二乗（L と同じ） |

- 効いたのは「**種類の違うモデルを混ぜること**」。CNN 単体は onset で LightGBM より弱いが、混ぜると ongoing・onset とも全条件で伸びた（第3章）。
- **その後の2回の提出（P、Q）は失敗**。どちらも M を下回った（第5章）。

## 3. L から M で変えたこと：Task 2 に時空間 CNN を追加

### 3.1 効果（公式に近い疑似評価、LightGBM 単体との IoU の差）

| | validation 1〜14日 | validation 全日 | private 1〜14日 | private 全日 |
|---|---|---|---|---|
| ongoing：0.5 × LightGBM ＋ 0.5 × CNN、しきい値0.60 | **+0.035** | **+0.034** | **+0.035** | **+0.036** |
| onset：0.7 × LightGBM ＋ 0.3 × CNN | +0.009 | +0.014 | +0.023 | +0.020 |

- 全体スコアの見込みは約 +0.008（見込み 0.877）で、実際は +0.0061（0.87505）。
- 混ぜる重みとしきい値は validation で決め、別のシミュレーション実行である private でも同じ値が最良だった。
- CNN は1本より3本の平均の方がよい（ongoing で +0.024〜0.031 → +0.034〜0.036）。4本目に別設定の CNN を足しても変わらなかった。
- CNN 単体の onset は LightGBM より弱い（0.62〜0.74 対 0.77〜0.82）。それでも重み0.3なら全条件で改善する。重み0.5では onset が悪化した。

### 3.2 CNN の中身

- **入力**：各窓の履歴（T−60〜T−5 の12スロット × リンク）を画像として扱う。チャネルは12個。
  - 速度 ÷ 自由速度、流量 ÷ 容量、観測ありの印、渋滞の印（速度 ≤ 0.6 × 自由速度）。見えていないセルは0。
  - リンクの静的な値5つ：車線数、車線あたり容量、自由速度、流入ランプ・流出ランプの有無。
  - 時刻（sin、cos）と週末の印。
  - **渋滞しやすさの確率（事前分布）は入れない。** 新しい実行では当てにならないため。
- **ネットワーク**
  - 1×1 の畳み込みで幅64に変換する。
  - リンク方向に膨張させた 3×3 畳み込みの残差ブロックを8個重ねる（膨張率 1, 2, 4, 8, 16, 1, 2, 4）。
  - 履歴方向を 12×1 の畳み込みで1つにまとめ、T+5〜T+30 の6ステップ × リンクの渋滞の確率を出す。
  - リンク方向は全層が畳み込みなので、1つのモデルで全パネルを扱える。パラメータは約64万。
- **学習**
  - 窓は train のもの。onset 窓はすべて、ongoing 窓はパネルごとに最大3,000。
  - 64リンクずつ切り出して学習する。バッチ32、AdamW、学習率 1e-3、OneCycle、3万ステップ。
  - 損失は「BCE（採点対象のセルのみ）＋ 0.5 × Lovász ヒンジ」。Lovász ヒンジは窓ごとの IoU を直接最適化する損失。
  - 2031年1〜2月の窓で早期終了する。
  - 乱数の種を変えて3本学習した。学習はリモートの RTX 6000 Ada で1本約17分（ローカルの 4090 なら約25分）。

## 4. M の中身（L との差分以外は前回レポートのとおり）

- Task 2 の LightGBM 部分は L と同じ。
  - onset：事前分布ドロップアウトで学習した5本の平均。
  - ongoing：事前分布なし、需要÷容量の特徴あり。
- onset の判定：`0.7 × LightGBM ＋ 0.3 × CNN` の確率を、L と同じ IoU 期待値最大化（`S_k / (k + P − S_k)` が最大の k 個）で選ぶ。
- ongoing の判定：`0.5 × LightGBM ＋ 0.5 × CNN` の確率が0.60以上のセルを渋滞とする（L は LightGBM 単体で0.65）。
- L と比べて変わるのは Task 2 の 685 セルだけ。

## 5. 失敗した提出（P、Q）

| 提出 | 内容 | Public LB | M との差 |
|---|---|---|---|
| P | ongoing を改良（LightGBM に路線全体の状態の特徴を追加、しきい値0.55）＋ onset に渋滞地図を追加 | 0.87429 | −0.0008 |
| Q | onset に渋滞地図を追加（ongoing は M のまま） | 0.87345 | −0.0016 |

- **渋滞地図**：その日の需要の状態（流量 ÷ train の平均）が似ている train の窓を40件探し、それらの T+30 の渋滞地点を平均した、状態に応じた事前分布。
  - onset の確率に 0.4 の重みで混ぜた。
  - 疑似評価では onset が +0.008〜+0.013 だったが、LB では −0.0016 だった。
- **P と Q の差から、ongoing の改良は LB で約 +0.0008 と読める。** 地図を除いた「M ＋ ongoing の改良」は、推定で約0.8758（未提出）。
- 公開 LB が採点するのは validation の公式の窓（onset・ongoing とも1パネル5窓）だけなので、ぶれが大きい。地図の疑似評価での伸びは主に private 側で出ていたが、公開 LB では確かめられない。**地図は採用を見送る。**

## 6. その後に分かったこと・伸びなかったこと（要約）

**評価方法についての新しい事実**
- 公式の窓の履歴は、Task 1 のマスクの対象外（別ファイルで公開）なので、約76%のセルが観測されている。一方、私たちの疑似評価の窓はマスク済みのデータから切り出していて、約52%しか観測されていない。
- マスクされた履歴を自前の Task 1 予測で埋めて評価し直すと、ongoing はどのモデルでも約 +0.02 高く出た。onset はほぼ変わらない。
- 教訓：モデルどうしの比較は、**埋めた履歴（公式と同じ条件）** でも確認すべき。

**伸びなかったこと**

| 試したこと | 結果 |
|---|---|
| 3つ目のモデル系統：Transformer（GRU ＋ パネル全体の注意機構） | マスク済みの履歴では ongoing が CNN より明確に良かったが、埋めた履歴では差がほぼ消えた |
| onset 専用に学習した Transformer | 1〜14日目では LightGBM 並みになったが、全日では届かない。乱数の種によるぶれも大きい |
| CNN の工夫：補助タスク、重みの移動平均、リンクの埋め込み、全体状態のチャネル | 乱数の種によるぶれの範囲 |
| onset を「どこが最初に崩れるか」の問題として学習：待ち時間つきの学習、窓内の順位、揺らぎ×上下流の不均衡の特徴 | 一貫した改善なし |
| onset の確率の較正 | 悪化 |
| しきい値の調整だけ（ongoing 0.60 → 0.50） | 小（全体で約 +0.001） |

**分かった事実**
- onset の損失の6〜7割は、窓の12%ほどで「別のボトルネックを選んで丸ごと外す」ことから来ている。
- 渋滞の起点の98〜99%は、train で頻出する上位10か所のボトルネックに入る。

## 9. 再現方法

**前提**：前回レポートの手順で L（`work\sub_L_ttt_t2K_t4ref\submission.csv`）と、Task 2 の LightGBM の確率（`work\sub_t2robust_bag5`、`work\sub_t2robust_bag5_stress`）ができていること。

1. **CNN を3本学習する**（GPU。1本約17〜25分）
   - PowerShell で環境変数 `T2CNN_LOVASZ=0.5`、`T2CNN_STEPS=30000` を設定し、`T2CNN_SEED` を 0、1、2 と変えて `.\.venv\Scripts\python.exe analysis\t2_cnn.py` を3回実行する。
   - 出力：`work\models\t2_cnn_lov.pt`、`t2_cnn_lov_s1.pt`、`t2_cnn_lov_s2.pt`（本番は `work\models_remote\` にコピーしたものを使用）。
2. **Task 2 を混ぜて予測する**
   - `.\.venv\Scripts\python.exe scripts\t2_cnn_blend_predict.py --cnn work\models_remote\t2_cnn_lov.pt work\models_remote\t2_cnn_lov_s1.pt work\models_remote\t2_cnn_lov_s2.pt --onset-probs-dir work\sub_t2robust_bag5 --ongoing-probs-dir work\sub_t2robust_bag5_stress --w-on 0.7 --w-og 0.5 --tau 0.6 --out-dir work\sub_t2M`
3. **L に組み込む**
   - `.\.venv\Scripts\python.exe scripts\swap_task_rows.py --base work\sub_L_ttt_t2K_t4ref\submission.csv --task queue --files work\sub_t2M\queue_validation.csv work\sub_t2M\queue_private.csv --out work\sub_M_ttt_t2cnnblend_t4ref\submission.csv`
   - 出力：`work\sub_M_ttt_t2cnnblend_t4ref\submission.csv`（367MB）。L との差は Task 2 の 685 セルのみ。

| ファイル | 役割 |

| `analysis/t2_cnn.py` | Task 2 の CNN の学習と評価（Transformer などの試験的な設定も環境変数で切り替え可能。既定値は M の設定） |
| `analysis/t2_blend_eval.py` | LightGBM と CNN の混ぜ方の評価（保存した確率から数秒） |

| `analysis/t2_imputed_eval.py` | マスクされた履歴を埋めた、公式と同じ条件での再評価 |
