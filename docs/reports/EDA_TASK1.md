## 2. データ・マスクの構造

### 2.3 リンクの並びと交通の向き
- `lwr_mainline_topology.csv` の `order_index` は、すべてのパネルで**距離標の昇順**。
- **N/E 方向のパネル**: order_index の昇順 = 上流 → 下流。
- **S/W 方向のパネル**: order_index の昇順 = **下流 → 上流**（交通は order_index が小さい方へ流れる）。さらに、パネル内の隣接リンク同士のつながりがトポロジーにごく一部しか記録されていない（例: D7_I10_W は107リンク中28のみ）。
- 渋滞の上流への伝播など、向きが重要なモデルを作るときは要注意。

### 2.4 時間的な傾向
- **月ごとのドリフトなし**: 1車線流量は 918〜937 veh/h、速度は約 111 km/h、渋滞率（速度 < 0.6×自由速度）は 3.6〜4.4% と、train から private まで安定。

## 3. 採点に関する注意（公式コードを読んで判明）

- 流量の RMSE は **(予測 − 真値) / 車線数** で計算します（1車線あたり）。車線数は `fd_parameters.csv` の `lanes`。
- **予測が欠けている（NaN）セルは 0 として採点されます**。必ず全ターゲットを埋めること。
- パネル×レジームごとにスコアを計算 → パネル内でレジーム平均 → ファミリー平均 → 5ファミリー平均。**小さいパネルも同じ重み**です。
- **Task 3 は Task 1 の答えから計算されます**。密度 = q/v、台数 N = k·L で、基本図（`fd_parameters` の三角形）との整合と保存則を見ます。
  - 自由流で速度 = 自由速度にすると、S_FD（基本図との整合）にも有利なはずです（発見4と整合）。
  - 手元の Task 3 評価は、主催者だけが持つ境界流量が無いと正しく計算できません（公式コードのコメントによると、真値でも S_LWR が 0 になる）。**Task 3 はローカルでは評価しにくい**。

## 4. 単純な手法の比較（train、10パネル）

公式と同じ集計方法（パネル → ファミリー → 全体の等重み平均）での S_state です。

| 手法 | S_state | 速度 RMSE (R1/R2/R3) | 流量 RMSE/lane (R1/R2/R3) |
|---|---:|---|---|
| 時刻平均（曜日×時刻×リンク）＝公式ベースライン相当 | 0.7203 | 9.6 / 9.5 / 9.7 | 93 / 95 / 96 |
| 空間補間（同時刻・距離で重み付け） | 0.8020 | 7.4 / 7.6 / 8.2 | 39 / 40 / 42 |
| 時刻平均 + 空間補間した残差 | 0.8631 | 4.6 / 4.7 / 5.1 | 42 / 43 / 44 |
| 時間補間と空間補間の平均 | 0.8802 | 4.1 / 4.2 / 4.5 | **35 / 35 / 37** |
| 時刻平均 + 時間補間した残差 | 0.8965 | 3.2 / 3.2 / 3.5 | 42 / 42 / 44 |
| 時間補間（eligible のみ使用） | 0.9054 | 2.6 / 2.7 / 3.1 | 43 / 44 / 48 |
| **時間補間（見えている全セル使用）** | 0.9089 | **2.5 / 2.6 / 2.9** | 42 / 43 / 46 |
| 速度 = 時間補間、流量 = 時間と空間の平均 | 0.9149 | 2.5 / 2.6 / 2.9 | 35 / 35 / 37 |
| **速度 = 自由流ルール、流量 = 0.5·Kalman + 0.5·空間** | **0.9183** | 2.4 / 2.4 / 2.8 | 35 / 35 / 37 |

わかったこと:
- 時刻平均（プロファイル）を足すと、かえって悪化します。**その日・その場所の直近の値の方がずっと情報量が多い**。
- 速度に空間補間を混ぜると悪化し、特に渋滞セルで大きく崩れます（渋滞の先端は空間的に鋭い）。
- 流量は空間補間が強く、隣接リンクの1車線流量の相関は 0.71〜0.97 です。

### 誤差の内訳（時刻平均 + 時間補間した残差）
- **渋滞セル（真の速度 < 0.6×自由速度）**: ターゲットの 4.1%。速度 RMSE 10.4 km/h（非渋滞は 2.8）、流量 70.8（非渋滞は 41.7）。
- **ギャップ長**: 1 → 12以上で、速度 RMSE 3.0 → 4.5、流量 40 → 51 と緩やかに悪化。
- **レジーム**: R3（50%マスク）でも R1 より 0.01 程度しか悪化しない。マスクが独立なので、近傍が十分残る。

## 5. ノイズの構造（改善の上限の目安）

### 5.1 速度
- 自由流（速度 > 0.85×自由速度）では、バリオグラム γ(h) が h = 1, 2, 3 で**ほぼ一定**（例: D12_I405_N で 0.678 / 0.681 / 0.680）。
  → **時間相関なし＝一定値＋白色ノイズ**。
- リンクごとの自由流の速度水準（中央値）は、**`fd_parameters.csv` の `free_speed_kmh` と平均差 ±0.8 km/h 以内**でほぼ一致（一部のリンクで最大14 km/h ずれる）。
- 自由流での速度と流量の相関は **ほぼ0**（−0.02〜0.03）→ 三角形の基本図どおり、自由流区間では速度が一定。
- ノイズの標準偏差（リンクごとの自由流の SD）: **0.84〜1.76 km/h**（パネルによる）。
- ⇒ 前後2点の線形補間より、**自由流と判定して自由流水準で埋める方が良い**。実際に自由流セルの RMSE は 2.32 → 2.12 に改善。

### 5.2 流量
- γ(h) が h にほぼ比例して増加（例: 802 / 1347 / 1881）→ **ランダムウォーク的な変動＋観測ノイズ**。
- h → 0 に外挿した切片（ナゲット）から推定したノイズ: **1車線あたり 15〜31 veh/h**。現在の RMSE（約36）はこれより大きく、まだ改善余地があります。
- 隣接リンク間で「ノイズ成分」（2階差分）の相関が、流量で 0.10〜0.35、速度で 0.34〜0.61 → 短い時間スケールの変動の一部は**隣のリンクと共通**。空間情報で単一リンクのノイズ下限より下げられる可能性があります。

### 5.3 上限の目安
速度誤差を約1.3、流量誤差を約21まで下げられたとすると、S_state ≈ 0.54×(1−1.3/25) + 0.46×(1−21/600) ≈ **0.956**。
現状は 0.918 なので、残りの伸びしろは約0.04（総合スコアでは ×0.35 で約0.013）。

## 8. 渋滞セルの改善（2026-09-14）

「渋滞」= 真の速度 < 0.6×自由速度（Task 2 の渋滞の定義と同じ）。リンクの並びは `common.oriented()` で上流→下流にそろえて分析しています。

### 8.1 誤差の出どころ（`05_congestion.py`）
速度誤差（自由流ルール(Kalman)、train 全ターゲット）の内訳です。

| 真の状態 | ターゲットの割合 | 速度 RMSE | 速度の二乗誤差に占める割合 |
|---|---:|---:|---:|
| 自由流（≥ 0.85×自由速度） | 95.0% | 2.2 | 63% |
| 部分渋滞（0.6〜0.85） | 0.2% | 7.7 | 2% |
| 渋滞（< 0.6） | 4.8% | 7.3 | **35%** |

渋滞セルを、前後の見えている時刻（同じリンク）のうち何個が渋滞しているかで分けると、はっきり分かれます。

| 前後の時刻の渋滞数 | 渋滞セルに占める割合 | 速度 RMSE | 渋滞の二乗誤差に占める割合 |
|---|---:|---:|---:|
| 2（両方渋滞＝渋滞の内部） | **93%** | 1.4〜2.0 | 6% |
| 1（片方だけ＝**渋滞の始まり・終わり**） | 6.6% | **24〜29** | **89%** |
| 0 | 0.1% | 約60 | 7% |

- 渋滞の内部はすでに解けている。**問題は境界セル**。
- 境界では、渋滞側（約40 km/h）と自由流側（約110 km/h）の間を線形補間すると中間（約75 km/h）になるが、真値はどちらか一方に寄っている → 大外れ。
- 同時刻の上下流の状態が判定の手がかり。前後の片方が渋滞しているとき、上下流の渋滞が 0個 → 渋滞している確率 12%、1個 → 62%、2個 → 92%。
- 検出: 「最寄りの4近傍（前・後・上流・下流）の最小速度比 < 0.9」で拾うと、**渋滞セルの 99.99% を捕まえられる**（対象はターゲットの約7%）。

### 8.2 渋滞の動き方（`05_congestion.py`, `06_transition.py`）
- 5分刻みでは渋滞の内部はほとんど動かない（ボトルネックに渋滞が立っている）。
- 境界の両側を比べると、**渋滞は常に下流側にある**。

| 事象 | 6リンク上流が渋滞している確率 | 6リンク下流が渋滞している確率 |
|---|---:|---:|
| 渋滞の始まり: 直前（t−1） | 0.22 | **0.40** |
| 渋滞の終わり: 直後（t+1） | 0.19 | **0.39** |

→ 渋滞の末尾が上流へ伸び（始まり）、下流へ縮む（終わり）。境界セルは「渋滞の末尾」なので、**上流と下流を区別した特徴量**が効く。S/W 方向のパネルは並びが逆なので、必ず向きをそろえること（2.3節）。

### 8.3 LightGBM で境界の領域を予測し直す（`features.py`, `07_lgbm_congestion.py`）
- **対象（region）**: 最寄りの4近傍の最小速度比 < 0.9 のターゲット（全体の約7%、train で230万行）。それ以外は従来のまま。
- **特徴量（80個、見えているセルだけから作成）**: 時間補間・Kalman・空間補間・現状ベストの値、最寄りの前後・上下流の速度比と距離、周囲（±2ステップ × ±3リンク）の速度比、周囲の1車線流量・占有率、時刻・曜日・車線数・自由速度・容量、上下流での車線数の変化、レジーム。
- **目的変数**: 速度は「速度 / 自由速度」、流量は1車線流量。全パネルをまとめて1モデル。
- **分割（日単位）**: 学習 2030-06〜11、早期終了 2030-12、**評価 2031-01〜02**（59日、710万ターゲット）。

| 手法（評価期間） | S_state | 速度 RMSE 全体 | 速度 RMSE 領域内 | 流量 RMSE 全体 | 流量 RMSE 領域内 |
|---|---:|---:|---:|---:|---:|
| 現状ベスト（LightGBM なし） | 0.9194 | 2.62 | 8.74 | 36.7 | 66.6 |
| 速度だけ LightGBM | 0.9399 | 1.65 | 3.54 | 36.7 | 66.6 |
| **速度・流量とも LightGBM** | **0.9414** | **1.65** | **3.54** | **34.6** | **47.1** |

- 領域内の速度誤差が 8.7 → 3.5 km/h に（−60%）。**S_state +0.022（総合スコアで約 +0.008）**。
- 重要度（gain）は時間補間の値が82%と最大。Kalman・空間補間・上下流の値がそれに続く。
- **答えの漏れがないことを確認済み**: ターゲットが「見えている」扱いのセルは0件。マスク版で見えている値は、マスクなし版と完全に一致（90/90）。

### 8.4 注意点
- **train の中での評価**です。train には Task 2 のギャップが無いので、validation/private では少し下がる可能性があります（2.2節）。
- 速度モデルは上限の4000回で止まっており、まだ伸びる余地があります。
- Task 3（物理整合性）への影響はまだ確認していません（ローカルでは正しく評価しにくい、3章）。

## 9. 流量を全セルで LightGBM に（2026-09-14、`08_flow_all.py`）

8章の後、失点は速度 約0.036・流量 約0.027 と、流量がほぼ同じ大きさになっていました。しかも流量は、境界の領域（7%）しかモデルで直していませんでした。そこで流量を全ターゲットでモデル化しました。

- **目的変数**: 従来の流量予測（0.5·Kalman + 0.5·空間補間）からの残差（1車線あたり）。
- **特徴量（60個）**: 前後・上下流の最寄りの見えている流量（従来予測からのずれ）と距離、周囲（±1ステップ × ±3リンク、±2ステップ）の流量、時間補間・Kalman・空間補間、周囲の速度比・占有率、車線数・容量・時刻など。
- **ランプの特徴量**: 車両保存にもとづく「上流の流量 + 間のランプ純流入」「下流の流量 − 間のランプ純流入」、リンク自身・隣のリンクのランプ純流入、間にある欠測ランプの数。欠測しているランプは0台ではなく、そのランプ自身の時間補間で埋めた。
- **データ**: 学習期間の10%を抽出（212万行）、早期終了は2030-12の10%、評価は2031-01〜02の全ターゲット（709万行）。速度は8章の方法のまま（速度 RMSE 1.646）。

| 流量の予測方法（評価期間） | S_state | 流量 RMSE 全体 | 境界の領域内 | 領域外 | R1 / R2 / R3 |
|---|---:|---:|---:|---:|---|
| 従来（0.5·Kalman + 0.5·空間） | 0.9399 | 36.65 | 66.6 | 33.6 | 35.4 / 36.2 / 37.3 |
| 境界の領域だけ LightGBM（07） | 0.9414 | 34.62 | **47.1** | 33.6 | 33.4 / 34.2 / 35.2 |
| 全セル LightGBM・ランプなし | 0.9440 | 31.24 | 49.1 | 29.6 | 30.3 / 30.9 / 31.7 |
| 全セル LightGBM・ランプあり | 0.9440 | 31.20 | 49.0 | 29.6 | 30.3 / 30.9 / 31.7 |
| **領域内は 07 + 領域外は全セル（ランプあり）** | **0.9441** | **31.01** | **47.1** | **29.6** | 30.1 / 30.7 / 31.5 |

わかったこと:
- 流量を全セルでモデル化すると、**誤差 34.6 → 31.0、S_state +0.0027**。改善のほとんどは、境界の領域外（93%のセル）の 33.6 → 29.6 から来ている。
- **ランプの流量はほぼ効かない**（誤差の差 0.04、S_state は同じ）。重要度の合計は7.8%あるが、ランプなしのモデルでも同じ精度が出るので、他の特徴量で代替できている。ランプの流量は平均 約54 veh/h と本線（約4,000 veh/h）に比べて小さく、隣のリンクの流量の差からほぼ推測できてしまうためと考えられる。
- 重要な特徴量は、隣接リンクの流量（`q_dn_dev`, 同時刻の ±2〜3リンク）、上流の流量＋ランプ（`q_up_cons_dev`）、前後の時刻の流量。**流量は空間方向の情報が中心**という EDA の結論（1章の3）と一致する。
- 境界の領域内だけは、渋滞に特化した 07 のモデルの方が良い（47.1 vs 49.0）ので、組み合わせを最終形とした。

### Task 1 の到達点
- ホールドアウトで **S_state 0.9441**（公式の時刻平均ベースライン相当 0.720、単純な時間補間 0.909）。
- ノイズから見た上限の目安は約0.956（5.3節）なので、残りの伸びしろは約0.015（総合スコアで約0.005）。
- 残りの失点（概算）: 速度 0.54 × 1.65/25 ≈ 0.036、流量 0.46 × 31.0/600 ≈ 0.024。

## 10. LightGBM / XGBoost / CatBoost の比較とアンサンブル（2026-09-14、`09_gbdt_compare.py`）

9章の最終形を構成する3モデル（境界の速度・境界の流量・全セルの流量）を、3つのライブラリで学習して比べました。

- **条件をそろえた点**: 特徴量・分割（学習 2030-06〜11 / 早期終了 2030-12 / 評価 2031-01〜02）・学習率 0.1・早期終了（100回）・上限 4000回。
  - 木の大きさは、LightGBM と XGBoost が葉の数 127（葉ごとの最小データ数 200 / 500）、CatBoost が深さ 8 の対称木。
  - LightGBM は 07・08 で保存したモデルをそのまま使用。
- **アンサンブルの重み**は早期終了用の 2030-12 の RMSE で決め（0.05 刻みの全探索）、評価期間には触れていない。

### 10.1 各モデル単体の RMSE（評価期間）

| モデル | LightGBM | XGBoost | CatBoost |
|---|---:|---:|---:|
| 境界の速度（km/h） | 3.544 | 3.542 | **3.520** |
| 境界の流量（veh/h/lane） | 47.06 | 47.12 | **46.99** |
| 全セルの流量（veh/h/lane、残差） | 31.20 | 31.22 | **30.99** |
| 学習時間（3モデル合計、Mac の CPU） | 約5分 | 約24分 | 約25分 |

### 10.2 Task 1 全体（評価期間、709万セル）

| 方法 | S_state | 速度 RMSE | 境界の速度 | 流量 RMSE | 境界の流量 |
|---|---:|---:|---:|---:|---:|
| LightGBM | 0.9441 | 1.646 | 3.544 | 31.01 | 47.06 |
| XGBoost | 0.9441 | 1.646 | 3.542 | 31.02 | 47.12 |
| CatBoost | 0.9444 | 1.643 | 3.520 | 30.91 | 46.99 |
| 平均（LightGBM + XGBoost） | 0.9445 | 1.634 | 3.460 | 30.90 | 46.57 |
| 平均（LightGBM + CatBoost） | 0.9448 | 1.628 | 3.412 | 30.80 | 46.32 |
| 平均（XGBoost + CatBoost） | 0.9448 | 1.628 | 3.412 | 30.81 | 46.38 |
| 平均（3つ） | 0.9448 | 1.625 | **3.392** | 30.79 | **46.21** |
| **重み付き（3つ）** | **0.9449** | **1.624** | 3.389 | **30.79** | 46.25 |

重み（LightGBM, XGBoost, CatBoost）: 境界の速度 (0.25, 0.30, 0.45)、境界の流量 (0.40, 0.35, 0.25)、全セルの流量 (0.15, 0.20, 0.65)。

わかったこと:
- **3ライブラリの差はごく小さい**（S_state 0.9441〜0.9444）。単体では CatBoost がわずかに最良。
- **アンサンブルは効くが、伸びは小さい**: 3つの平均で +0.0007、重み付きで +0.0008。重みを最適化しても単純平均とほぼ同じ（差 0.0001）なので、**単純平均で十分**。
- 伸びは主に境界の領域（速度 3.54 → 3.39）から。モデルの違いによる誤差のばらつきが平均で打ち消し合う。
- LightGBM と XGBoost の平均は伸びが小さい（0.9445）。似た木の作り方（葉ごとの成長）なので、誤差の傾向も似ている。**CatBoost（対称木）を混ぜると伸びる**。
- チームレポートによると、平均で誤差のばらつきが減ると Task 3 の保存則の項（S_LWR）も伸びるので、提出では S_state の +0.0008 以上に効く可能性がある（手元では未確認）。
- 境界の速度モデルは、3ライブラリとも上限の4000回で打ち止め。学習回数を増やせばまだ伸びる余地がある。
