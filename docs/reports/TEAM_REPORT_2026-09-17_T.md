# TrafficFlowBench：現ベスト（Public LB 0.87778、提出 T）の手法と、その後の検証結果

作成日：2026-09-17。対象コンペ：Kaggle「2026 IEEE Big Data - Traffic Flow Bench」。
前レポート（`TEAM_REPORT_2026-09-16_R.md`、ベスト 0.87687）の続きです。

---

## 1. 結論（先に要点）

- **現在のベストは Public LB 0.87778（提出 T）**。R（0.87687）から **+0.00091**。
- T の変更点は Task 2 の2か所です。Task 1・3・4 は R と同じです。
  1. **onset の CNN を「過去日で自己教師あり適応した CNN」に置き換えた**（本レポートの主題、以下「⑨b」）
  2. ongoing の Transformer を 4本 → 8本（seed s3〜s10）に増やし、重みとしきい値を調整した
- **onset 側の変更が LB に転移したのはこれが初めて**です。前レポート第7章の「onset の改善は転移しない」という経験則を破りました。
  - これまでの失敗は、渋滞地図・ゲート・順位付けといった「判定」の変更でした。
  - ⑨b は、その run に合わせて「モデルの重み」を変えます。
- その後、⑨b を発展させる試み（TTA 7案）と、onset を「複数のあり得る未来」として扱う試み（多峰性 4案）を検証しました。**どちらも T を両月で上回るものはありませんでした**（第6章）。

### 3.2 過去日適応 CNN（⑨b）とは

**動機**：validation / private は train と別のシミュレーション run です（note 17）。当初は「表現そのものが違う」と考え、別の表現を学ばせる案を試しましたが、すべて悪化しました（Task 1 トランクの移植、history/future 対照学習、Task 1/2/4 同時学習）。
そこで「**同じ表現のまま、パラメータをその run に少しだけ寄せる**」方針に切り替えたのが ⑨b です。

**モデル**（`t2_cnn_lov_rec_s20.pt`）：
- 既存の Task 2 CNN（12スロット×リンクの画像を入力にし、1×1 conv → 膨張畳み込みの残差ブロック8段 → 時間方向を畳む → 6地平線の渋滞 logit を出す）に、**再構成ヘッド**（1×1 conv）を追加しました。
- 再構成ヘッドは、履歴セルの 20% を入力から隠し、その v/vf と q/cap を復元します。
- 学習時の損失は BCE ＋ 0.5 × Lovász ＋ 0.3 × 再構成、30k step、seed 20 です。
- 再構成ヘッドを付けただけでも、CNN 単体の性能は上がりました（onset +0.013/+0.019、ongoing +0.009/+0.012）。

**推論時の適応**（パネル×スコア月ごと、`scripts/t2_adapt_official.py`）：
1. 公式窓のある日を日付順に処理する。
2. 日 d の窓を、**現在の重み**で予測する。
3. その後、d より**厳密に前の日**の released 層（masked）から、ランダムな時刻の履歴窓を16個切り出す。
4. 再構成損失**だけ**で 30 step 更新する（AdamW、lr 1e-4）。
5. 重みは翌日に持ち越す。

- **Task 2 のラベルは一切使いません**。使う情報は過去日の交通の動き（速度・流量）だけで、渋滞の場所も使いません。
  - 過去日の渋滞場所を使うと「いつもの場所」バイアスが強まることを note 59 で確認済みです。
- データ利用ルール（「スコア月のデータは厳密に過去の日だけ」）の範囲内です。
- Task 2 の出力を変えるのは入力層と残差ブロックの更新だけです（再構成ヘッドの更新自体は出力に影響しません）。

**局所評価**（公式に近い onset 窓、validation 169 / private 162）：

| | validation | private |
|---|---|---|
| CNN 単体：適応なし → 適応あり（両月合算 331窓） | 0.7314 → 0.7799（+0.0485、窓単位 CI [+0.026, +0.072]） | ← 両月合算 |
| ブレンド内（0.7×H ＋ 0.3×CNN）：CNN×3 → 適応 CNN | +0.0079 | +0.0189 |
| 同じモデルを適応なしで使った場合（対照、9/17 再測定） | −0.0049 | **−0.0207** |

適応をやめると private の onset が大きく落ちます。**効いているのは「適応」そのもの**です。

### 3.3 再現手順

```bash
.venv/Scripts/python.exe scripts/t2_adapt_official.py --out-dir work/sub_t2adaptcnn        # ⑨b（環境変数 T2CNN_REC=0.3 T2CNN_LOVASZ=0.5）
.venv/Scripts/python.exe scripts/t2_cnn_blend_predict.py \
  --cnn <CNN×3> --og-nets <CNN×3> --og-arch cnn \
  --og-nets2 <Transformer s3..s10> --og-arch2 tfm --w-og2 0.60 \
  --onset-probs-dir work/sub_t2robust_bag5 --onset-cnn-probs-dir work/sub_t2adaptcnn \
  --ongoing-probs-dir work/sub_t2gs --w-on 0.7 --w-og 0.20 --tau 0.50 --out-dir work/sub_t2S2
.venv/Scripts/python.exe scripts/swap_task_rows.py --base work/sub_R_ttt_t2ens_t4ref/submission.csv \
  --task queue --files work/sub_t2S2/queue_*.csv --out work/sub_T_ttt_t2adapt_t4ref/submission.csv
```

- `<CNN×3>` は `work/models_remote/t2_cnn_lov{,_s1,_s2}.pt`、Transformer は `t2_cnn_lov_tfm_s{3..10}.pt` です。
- 予測スクリプトに `--onset-cnn-probs-dir` を追加しました。適応モデルは日ごとに重みが変わるため、1つのチェックポイントからは onset 確率を再計算できないからです。

## 6. その後の検証（T を上回る案はなし）

Ada 上で、チームメイトが実行・報告した結果です（`tta_lab/reports`、`mm_lab/reports`、note 72/73）。

### 6.1 ⑨b の発展（TTA）

| 案 | 内容 | 結果 |
|---|---|---|
| A | 当該 run に適応させた Task 1 の残差を onset 特徴に | 効果なし |
| B | 予測する窓自身の履歴で直前に数 step 追加適応 | 両月で改善せず |
| C | 更新対象を小さく（GroupNorm、FiLM、LoRA、Adapter、入力較正など7種） | すべて全体更新より悪い |
| D | 適応損失に次ステップ予測・差分を追加 | +0.0026/+0.0021（CI は 0 を跨ぐ）。⑨b 自体の乱数ぶれ（約 0.001）と同程度で打ち切り |
| E | 適応手順のメタ学習 | SGD の内側ループは lr 1e-3 で無効、3e-3 以上で発散。安定する AdamW 5 step では、予測の動きが ⑨b の約1/10。打ち切り |
| F | 複数の適応軌道を、現在窓の再構成誤差で重み付け | CNN 単体では良いが、ブレンドでは悪化 |

**結論**：⑨b の形（全体更新、再構成損失、日次累積）が現時点の最適です。

### 6.2 onset の多峰性仮説

仮説：外した onset は「同じ履歴から複数のボトルネックがあり得る」多峰的な問題で、単一の確率マップは最頻モードに潰れる。

| 診断・案 | 結果 |
|---|---|
| 似た履歴の検索（train） | 外し窓の62%で、正解が近傍の上位3モードに入る。ただし最頻モードの割合は約0.85 |
| **T 自身の順位** | **外し窓の85%で、正解は T の上位3ピークに入っている** |
| K 本の onset ヘッド（K=1/3/5） | 候補は多様化したが、private で選べない（選択器の性能は −0.04〜−0.15） |
| 流量を微増させたときの崩れやすさ | T の順位を上回らない |
| 適応前後の logit 差 Δ で補正（`logit p_T + λΔ~`） | 3 seed の交差月評価で validation +0.013〜+0.017、private +0.0003〜+0.0044。**唯一残った候補**だが、LB 換算で +0.0002 前後 |

**結論**：onset の失敗は「候補を思いつけない」ことではなく、「**T の上位2〜3候補からどれを選ぶか**」です。その選択を private まで汎化させる方法は、まだ見つかっていません。
