## 0. 前提：なぜこの実験をやるのか

### 0.1 これまでの実測

| 何を変えたか | 案 | 結果 |
|---|---|---|
| 別の表現を学ばせる | ①Task1トランクの移植、⑤history/future対照学習、⑩Task1/2/4同時学習 | すべて悪化 |
| 表現はそのまま、パラメータを当該runに少し寄せる | **⑨b 過去日の自己教師あり適応** | onset単体 **+0.0485**、M-blend内 +0.0079（val）/ +0.0189（priv）、**public LB +0.00091（候補T = 0.87778）** |
| レア渋滞を「見つける」能力を上げる | ⑥⑦ | 見つける力は上がる（見逃し窓でtop-1 0.05→0.30）が、スコアに変換されない |

### 0.2 ここから導く作業仮説

train と validation/private の差は「交通の表現が違う」ことではなく、「**同じ表現のパラメータを、そのシミュレーションrunに少しだけ合わせる必要がある**」こと（パラメータレベルのシフト）。
しかもそのシフトは、スコア対象月の**過去日の未ラベルデータ**から推定できる。
⑨bは、onset側の変更として初めて private 疑似評価で再現し、public LB も動かした。この手法をもっと本格的な交通向けTTAに育てるのが A〜F の目的。

### 0.3 idea 9b の正確な手順（全実験の土台）

- モデル：`work/models/t2_cnn_lov_rec_s20.pt`
  - `T2CNN_REC=0.3 T2CNN_LOVASZ=0.5 T2CNN_SEED=20` で学習した CNN（`analysis/t2_cnn.py` の T2Net）。
  - 通常の queue ヘッドに加えて、**再構成ヘッド `rec`**（1×1 conv、出力2ch＝v/vf と q/cap）を持つ。
  - 学習時は、履歴セルの20%を隠して復元する損失を 0.3 倍で足している。
  - s21 / s22 も同じ設定で学習済み（Ada の work/models にある）。
- 入力：`(B, C=12, H=12, S)`。ch0 v/vf、ch1 q/cap、ch2 観測フラグ、ch3 渋滞フラグ（v≤0.6vf）、ch4–8 静的リンク特徴、ch9–11 時刻 sin/cos と週末フラグ。未観測セルは0。
- 適応の手順（パネル×スコア月ごと）：
  1. 公式風ウィンドウを持つ日を昇順に処理する。
  2. 各日 d で、まず**現在の重み**で d のウィンドウを予測する。
  3. 次に、d より**厳密に前の日**（0…d−1）からランダムに 16 窓を切り出す（時刻もランダム）。masked layer の履歴だけを使い、ラベルは一切使わない。
  4. その窓で 30 step 適応する（AdamW、lr 1e-4、wd 1e-4）。損失は「20%セルを隠して v/vf, q/cap を復元」の MSE で、観測セル×隠したセルだけに掛ける。
  5. 重みは翌日へ持ち越す（累積・因果的）。
- 更新対象：optimizer には全パラメータを渡しているが、勾配が流れるのは `inp`・`blocks`・`rec` だけ（`collapse`・`head` は rec 損失の計算グラフに入らないので動かない）。
- 重要な帰結：**Task 2 の出力を変えるのは `inp` と `blocks` だけ**。`rec` だけを動かしても Task 2 の予測は変わらない（C 案で効いてくる）。

### 0.4 データ利用ルール（全実験で厳守）

- Task 2 の予測に使ってよいのは、そのウィンドウの履歴 T−60…T−5 と、train から学んだもの。
- スコア対象月の released データは、**そのウィンドウの日より厳密に前の日**だけ使ってよい（ユーザー決定 2026-09-14）。
- 使ってはいけないもの：slot T、ホライズン／バッファの ramp flow、post-buffer（T+95以降）の mainline、同日の他時刻データ。
- スコア対象月は「手法の導出・評価」には使ってよいが、「提出モデルの教師あり学習」には使ってはいけない。自己教師あり適応（ラベル不使用）は⑨b・T1 TTT と同じ扱いで許容済み。
- **疑似評価特有の注意**：公式風ウィンドウ（`first_onsets` / `ongoing_official`）のラベル（T+5…T+30）は、スコア月の masked layer にそのまま載っている（公式窓ではないのでブランクされていない）。
  - そのため、予測時に「その日の履歴12スロット以外」を1セルでも見ると、**疑似評価に直接ラベルが漏れる**。
  - 本番では漏れないので、疑似評価だけが良く見える偽陽性になる。

### 0.5 【重要】既存の t1res 特徴（note 63/64、②③）にリークがある

- `work/sub_m3v1` などの Task 1 再構成は、M3 CNN が**丸1日（288スロット）の画像**を入力にして出力したもの。
- M3 のブロック dilation は時間方向に (1,2,4,8,16,32,1,2,4,8,16,1)。2本目の 3×3 conv も含めると、**時間方向の受容野は片側 約107スロット**。
- したがって履歴スロット T−5 の再構成値は、T+102 までの観測の影響を受けている。
  - スコア月の疑似窓：ホライズン T+1…T+6 がブランクされていないので、**ラベルそのものを見ている**。
  - 公式窓：T+1…T+18 はブランクだが、T+95〜T+102（post-buffer）は見えている。これは禁止ルート。
  - train 月：ホライズン自体がブランクされていない（note 08）ので、未来の値を見ている。
- 結論：note 64 の「+0.0025〜+0.0069 family」は、リーク込みの数字の可能性が高い。候補S（t1res入り）は提出していないので実害はない。
- **A 案では、Task 1 への入力を「そのウィンドウの履歴12スロットだけ」に制限すること**（§A.2）。

## 1. 評価の共通仕様（全実験）

- 窓：blank-aware 公式風窓。
  - onset：validation 169 / private 162 窓（1日1窓、その日の最初の渋滞発生）。
  - ongoing：validation 3351 / private 3374 窓。
  - 対象は 8 パネル（D7_I10_E/W, D7_I210_E/W, D7_I405_N/S, D12_I5_N/S）。
- 指標：
  - onset は T+30 のみ。expected-IoU の ratio ルール（`select(p, "ratio", 1.0)`）で選んだリンク集合の IoU。
  - ongoing は T+5…T+30 の 6 ステップで、`p ≥ τ` の IoU。
  - **family mean**（パネル群平均）が公式スコアで使われる値。Δtotal = 0.15 × Δ(onset または ongoing の family)。
- 比較の基準（REF）＝候補T（現ベスト 0.87778）の該当スロット：
  - onset T-blend = 0.7 × LightGBM H（キャッシュ `t2probs_*` の on_p）+ 0.3 × ⑨b 適応CNN（キャッシュ `t2cnn_t2_cnn_lov_adapt_*`）
  - ongoing T-blend = 0.20 × gs1 + 0.60 × tfm s3–s10 平均 + 0.20 × cnn3、τ = 0.50
  - 新しい実験 X の評価では、onset は ⑨b の枠を X で置き換え、ongoing は cnn3 の枠を X で置き換える。
  - 「alone」（X 単体）も併記する。
- 統計：窓単位の対差分を 2000 回ブートストラップして 95% CI を出す。
- 判定の目安（note 58 の較正則）：
  - ローカルの公式風の改善は、LB では約半分になる。
  - onset は窓数が少なく、prior-dropout の乱数だけで 0.08 動いた実績がある（note 22）。
  - **両月で同符号、かつ CI が 0 をまたがない**ことを最低条件にする。
- ⑨b 自体の再現性チェック：`run_adapt.py --name rep9b`（既定値）が、キャッシュ `t2_cnn_lov_adapt` とほぼ同じ数字になることを最初に確認する。乱数系列が違うので完全一致はしない。

## A. adapted Task1 residual（②×⑨b）— 最優先

### A.1 狙い

- ②の残差 `r = x_obs − x̂_Task1(global)` には、runのオフセットがまるごと乗る。例えば run 全体が 1% 速ければ、全リンクに +1% が出る。
- 当該runに適応させた再構成器の残差 `r_adapt = x_obs − x̂_Task1(adapted)` なら、run の水準は吸収され、「**このrunにとって異常な部分**」だけが残る。
- これは notes 59/60 で、需要や過去活動から手作業で作ろうとして失敗した「水準ではなく異常」という量そのもの。
- ②も⑨bもそれぞれ陽性だったので、単純な加算以上になる可能性がある。ただし②の陽性はリーク込みの可能性がある（§0.5）ので、まずリークのない②を作り直すところから始める。

### A.2 作り方（手順）

1. **Task 1 モデル**：`tta_lab/assets/t1/` の3本を使う。
   - `m3v1_seed0_w64.pt`、`m3v1_seed1_w64.pt`（`analysis/t1_m3_cnn.Net(cin=10, c=64)`）
   - `m3w128_seed0_w128.pt`（`c=128`）
   - いずれも `M3_V2` は未設定（v1 入力）で、10ch 入力、出力は速度偏差 / 車線あたり流量偏差。
2. **ベース（プロファイル）**：パネルごとに train の真値で `tfb.features.profile_table(true_speed, truth_valid(z), weekday, 全日)` を作る（flow も同様）。対象日の曜日で引いて `base_v, base_q` (T, S) とする（`scripts/t1_m3_predict.py:train_part` と同じ）。
3. **因果的な入力画像（リーク対策の本体）**：各ウィンドウ (d, T) について、288×S の空画像を作る。
   - **履歴 T−60…T−5 の12スロットだけ**に v, q, occ を入れ、それ以外は全部 NaN（＝不可視）にする。
   - `m3.make_inputs(zz, base_v, base_q)` に渡す。zz は `obs_speed/obs_flow/obs_occ/lanes/free_speed` だけを持つ辞書。
   - train 窓では `hist_from_truth` と同じ真値層（true_speed / true_flow / true_occ）を使う。スコア月では obs 層を使う。
   - 同日の T−60 より前のデータを使うかは未決（ユーザー判断事項）。既定では使わない。
4. **再構成と残差**：`out = net(X)` から `pv = base_v + out[:,0]*10`、`pq = base_q + out[:,1]*100*lanes` を計算し、履歴12スロットを取り出して `r = obs − pred` とする。
   - モード `visible`（既定、note 63 と同じ）：観測セルをそのまま入れて再構成する。
   - モード `hidden`：観測セルの 20% を隠す乱数マスクを K=4 回かけ、隠れたセルの予測だけを平均する。本来の「予測残差」になる。
5. **特徴量**：`analysis/t2_onset_t1res_feats.py:t1_feats` と同じ 12 列（rv3, rv12, av3, av12, rq3, sd6, sig, mix と scale-free の av3_rel, mix_rel, av3_rk, mix_rk）。
   - 3本の平均を予測、標準偏差を sig とする。
   - **既定は scale-free の4列（COLS=8:12）**。理由：Task 1 は train run で学習しているので、train 上の残差はスコア月の約 1/1.4 しかなく、生の水準は移らない。
6. **適応版（adapted）**：スコア月ごと・パネルごとに、⑨bと同じ日次ループを Task 1 の3本に対して回す。
   - 日 d のウィンドウの特徴を、現在の重みで計算する。
   - その後、d より前の日の**フル日画像**（masked layer、`make_inputs(z_split)`。過去日なので全スロット使用可）から、8日分・64リンククロップをサンプルする。
   - 観測かつ eligible なセルの 20% を隠し、その偏差（入力 ch0/ch1 と同じ単位）を MSE で復元する（`LOSS_W=(0.75,0.25)`）。AdamW lr 1e-4 で 30 step。重みは持ち越す。
   - `--order adapt-then-predict` も比較する。
7. **train 側の特徴**：
   - 既定は global モデルのまま（`--train-adapt none`）。根拠：train run 上では、global モデル自体がその run に適応済みのモデル。
   - この場合 LightGBM の学習データは global 版と adapted 版で**同一**になり、違いはスコア月の推論特徴だけになる。比較としてきれい。
   - 余力があれば train 月でも日次適応した版（`daily`）を作る。ただし日数が多く（約270日×8パネル×3本）重い。
8. **LightGBM（対比較）**：`analysis/t2_onset_combo_eval.py` の構造をそのまま使う。
   - H 設定：600 rounds、63 leaves、`t2_shift_remedies.PARAMS`、prior dropout（`t2_prior_robust.dropout_prior`）。
   - 5 bags × **3 seeds**。同じ seed・bag では、base と +t1res で**同じ dropout 乱数**を使う（note 69 の教訓：キャッシュ済み H と比べると乱数差 0.004〜0.008 family に埋もれる）。
   - 学習窓はパネルあたり最大 2000 の onset 窓（`ctx.eo`）。
9. **比較する腕**（すべて同じ bag 乱数）：

| 腕 | LGBM学習特徴 | スコア月の推論特徴 |
|---|---|---|
| base | H | H |
| glob-causal | H + t1res(global, 履歴12のみ) | global |
| adapt-causal | 同上（train-adapt none なら同一モデル） | adapted |
| (参考) leaky | H + t1res(sub_m3v1 丸1日) | 丸1日 ← **提出不可、リーク量の測定用** |

   - 出力：onset alone と、0.7×LGBM + 0.3×⑨b適応CNN（＝候補T枠）での IoU / family と、base に対する差分（3 seed 平均、何 seed 中何 seed が正か）。
   - 参考として、キャッシュ H + ⑨b（＝候補T そのもの）も並べる。

### A.3 判定

- adapt-causal − glob-causal が両月とも正なら、仮説（run 水準の吸収が効く）を支持する。
- adapt-causal − base が family で **+0.01 以上**あれば、提出候補を作る価値がある。note 69 の結論：それ未満は dropout 乱数に埋もれるので、多数ドローの平均が必要になる。
- leaky と glob-causal の差が大きければ、note 64 の陽性はリーク由来だったと確定する（ノートに記録すること）。

### A.4 実装状況

**`tta/run_A_t1res.py`**（§A.2 の 1〜9 を実装。構文チェックのみ）。例：`python tta/run_A_t1res.py --name A_sf`、`--cols all`、`--resid hidden`、`--order adapt-then-predict`。leaky 腕は Ada にキャッシュが無いため未実装。元にした部品：

- `t2_onset_combo_eval.py`（対比較 LGBM の骨格）
- `t2_onset_t1res_feats.py:t1_feats`（特徴計算。PV/PQ を渡す形に直す）
- `t1_m3_cnn.make_inputs / Net`
- `tta/common.py`（評価まわり、キャッシュ読み）

コストの目安：train 特徴は 8パネル × 2000窓 × 3本 × 288×S 画像を batch 16 で推論するので数分。hidden モードはその4倍。適応は 16 パネル×月 × 約30日 × 3本 × 30 step で、GPU 1枚で数十分。

## B. 現ウィンドウでの micro-adaptation

### B.1 狙い

- 過去日適応（⑨b）の後、さらに**予測する窓自身の履歴**（T−60…T−5、未来なし）で 1〜5 step だけ自己教師あり更新してから予測する。
- 「その瞬間のドメイン状態」に合わせる。合法で、ラベルは使わない。

### B.2 手順（`run_adapt.py --micro K`）

1. 日次の過去日適応は ⑨b と同じ（またはその変種）。
2. 窓 j ごとに、学習対象パラメータを退避する。
3. 窓 j の入力 x_j を `--micro-bs`（既定8）回複製してバッチにする。複製ごとに違う 20% マスクがかかる。これで K step（AdamW、`--micro-lr`）更新する。
4. 予測し、fixed-mask の再構成損失（F 用）を記録してから、パラメータを戻す。
5. 既定は onset 窓だけ（1日1窓なので安い）。ongoing は `--micro-kinds both`（1窓ずつ直列なので時間がかかるが、6700窓×数step なら数分〜十数分）。

### B.3 注意

- **同日の複数窓を一括で適応してはいけない**。例えば 17:00 の窓の履歴で適応してから 8:00 の窓を予測すると、同日の未来データのリークになる。実装は窓ごとに直列で処理している。
- 12スロット×S セルしかないので、全パラメータを動かすと過適合しやすい。C 案（norm / film / incal など小さいモジュール）と組み合わせるのが本命。
- 探索グリッド例：K ∈ {1, 3, 5}、micro-lr ∈ {1e-5, 1e-4, 1e-3}、mode ∈ {full, norm, film, incal}。
- 判定：同じ日次適応で micro なし（K=0）との対差分を見る。

## C. パラメータ効率的適応（PEFT）

### C.1 狙い

- シフトが「run 固有の較正」（速度スケール、流量スケール、時間応答性、空間結合）だけなら、小さいモジュールを動かすだけで全体更新と同等以上になるはず。
- 過適合が減るので、B を安全に行えるようになる。

### C.2 モード（`run_adapt.py --mode`）

| mode | 動くパラメータ | 概要 |
|---|---|---|
| full | inp + blocks + rec | ⑨b そのもの（基準） |
| last2 | blocks[6:8] | 最後の2ブロック |
| norm | blocks 内の GroupNorm γ, β | 「ブロックごとの scale/bias」 |
| film | 各ブロック出力の per-channel γ, β（新設、恒等で初期化） | FiLM |
| lora | 各ブロックの 3×3 conv 2本に W + BA（rank r、B=0で初期化） | LoRA |
| adapter | 各ブロックの後に c→16→c ボトルネック（up=0で初期化） | Adapter |
| inp | 入力 1×1 conv | 入力較正（チャンネル混合） |
| incal | v/vf と q/cap にチャンネルごとの a·x+b（観測セルのみ、4パラメータ） | 最も字義どおりの「速度・流量スケール較正」 |

- full 以外では **rec ヘッドを凍結**する（既定）。rec を動かすと、自己教師あり損失を rec だけで吸収してしまい、Task 2 に効く部分が動かなくなるため。`--train-rec 1` で比較できる。
- 学習率は小モジュールほど大きくする必要がある。目安：full 1e-4、last2 1e-4〜3e-4、norm/film 1e-3〜3e-3、lora/adapter 3e-4〜1e-3、incal 1e-3〜1e-2。steps は 30 と 100。

### C.3 判定

- full（rep9b）との対差分を、onset/ongoing・両月で見る。
- 小モジュールが full と同等なら、「較正仮説」を支持。そのモジュールを B / E の標準にする。

## D. 適応損失の拡張

### D.1 狙い

- masked reconstruction は「状態」を復元する。
- Task 2 は「変化」を当てるタスクで、onset は v より dv/dt・dq/dt に依存する。
- 自己教師あり損失にも時間発展を入れる：
  `L_adapt = L_mask + λ1·L_nextstep + λ2·L_Δ`

### D.2 定義（`common.ssl_loss`）

- **L_mask**：⑨b と同じ。
- **L_next**：履歴の末尾 k スロット（`--k-tail`）を全セル隠し、rec ヘッドで復元する（隠した観測セル上の MSE）。
  - 窓の中での「次ステップ予測」になる。履歴内だけで完結するので、未来は使わない。
- **L_Δ**：同じ入力に対する予測の差分 `(x̂_t − x̂_{t−1})` と真の差分 `(x_t − x_{t−1})` の MSE。末尾 k スロット上で、t と t−1 の両方が観測されているセルだけを使う。
  - k=1 のとき、x̂_{t−1} は「見えているセルの再構成」になる。
- 注意：rec ヘッドは学習時に「ランダム20%隠し」しか見ていないので、末尾隠しの復元は初期状態では下手。そこを適応で学ばせることが狙い。

### D.3 グリッド例

`--losses MASK NEXT DELTA` ∈ {(1,0,0), (1,0.5,0), (1,0,0.5), (1,0.5,0.5), (0,1,1)}、`--k-tail` ∈ {1, 2, 3}。
Δ はスケールが小さいので、λ2 は 1〜5 まで振ってよい。

## E. メタ学習による適応

### E.1 狙い

- ⑨b は「たまたま効いた適応」。これを「効くように設計された適応」に変える。
- 内側ループで自己教師あり適応を行い、外側ループで「適応後の Task 2 損失」を最小化する。
- Task 2 ラベルは外側ループ（train run）にしか出てこないので、テスト時の手順は⑨bと同じで合法。

### E.2 手順（`run_E_meta.py`）

1. エピソード ＝（パネル p、train 月の日 d≥1）。
2. **内側**：d−14…d−1 日の train **masked** 層（テスト時と同じ released 層）から 16 窓を切り出し、`common.ssl_loss` で k 回 SGD（lr α）。`--inner-scope` で full / norm / last2 を選ぶ。
3. **外側**：日 d の train 窓（onset + ongoing、64リンククロップ）16 個に、**適応後の重み**で BCE + 0.5·Lovász を計算する。
   - さらに `rec_w`（0.3）× 適応前重みでの L_mask を足し、rec ヘッドを生かし続ける。
   - AdamW lr 1e-4。初期値は rec_s20。
4. `--order 1`（FOMAML：内側勾配を detach）または `2`（二次、内側 k は小さく）。
5. **run シフトの模擬（`--aug`）**：train は1つの run しかないので、そのままでは「run 間シフト」を学べない。
   - エピソードごとに v/vf と q/cap チャネルへ `exp(U(−aug, aug))` を掛ける（チャネルごとに1係数、内側・外側の入力に同じ係数）。
   - ラベルは変えない。＝「表現の較正がずれた状態を、自己教師あり適応で戻す」ことを学ばせる。
   - 限界：ch3（渋滞フラグ）は再計算しないので、完全に整合した摂動ではない。
6. 500 step ごとに `runs/<name>/meta_step*.pt` を保存する。
7. **評価**は、学習時の内側ループと同じ条件で行う：
   `run_adapt.py --ckpt runs/E_meta/meta.pt --opt sgd --lr α --steps k --reset-daily --mode <inner-scope>`
   - 比較対象は、同じ条件で rec_s20 を使ったもの（メタ学習なし、`--reset-daily --opt sgd`）と、rep9b。
   - `--no-adapt` で「メタ学習後、適応なし」も測る。メタ学習はそれ自体が表現を変えるので、その効果と分離するため。

### E.3 リスク

- 単一 run なので、日ごとの差は run 間差より小さい。aug なしだと何も学ばない可能性がある。aug ∈ {0, 0.05, 0.1, 0.2} を振ること。
- 外側で Task 2 損失を追加学習するため、適応とは無関係に CNN 自体が変わる（ES なし）。必ず `--no-adapt` の対照を取ること。
- 規模感：3000 outer step × (内側 k 回 + 外側 1 回)。GPU 1 枚で数十分程度の見込み。

## F. 適応軌道のアンサンブル（自己教師あり損失ゲート）

### F.1 狙い

- 設定の違う複数の適応モデル M_k を作る（最後の日だけ／全過去日／norm だけ／小lr／大lr／損失違い など）。
- 窓ごとに、**予測時に観測できる**現ウィンドウの自己教師あり損失 L_k で重み付けする：
  `w_k ∝ exp(−β·L_k)`
- notes 51/65 で失敗したゲートは、169窓から「どの Task 2 予測が正しいか」を推測しようとしていた。今回は Task 2 と独立に観測できる量で重み付けする点が違う。

### F.2 手順

1. `run_adapt.py` で K 個の run を作る。各 run は窓ごとの `on_ssl/og_ssl` を保存する（同じ固定マスク seed なので run 間で比較可能）。候補：
   - `rep9b`（既定）
   - `--window-days 1`（直近1日のみ）
   - `--window-days 7`
   - `--mode norm --lr 1e-3`
   - `--lr 3e-5`、`--lr 3e-4`
   - `--losses 1 0.5 0.5`
   - `--order adapt-then-predict`
   - rec_s21 / rec_s22 の `--ckpt`（seed 違い。U 候補の素材にもなる）
2. `run_F_gate.py --runs ... --name F_gate` を実行する。
   - L_k を窓ごとに run 間の中央値で割って規格化する（β をスケール不変にするため）。
   - β ∈ {0, 1, 3, 10, 30, 100} を各月で評価する。
   - **もう一方の月で選んだ β** を適用して保存する（cross-split、過適合防止）。
   - 一様平均（`<name>_uniform`、β=0 と同じ）も保存し、全部をまとめて report する。
3. 判定：
   - gated が uniform より両月で良ければ、ゲートの価値がある。
   - uniform が rep9b より良いだけなら、単に seed / 設定のアンサンブル効果（U 候補と同種）。
